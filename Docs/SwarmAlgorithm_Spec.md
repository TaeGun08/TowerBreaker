# 기술 명세서: 군집(Swarm) 알고리즘의 원리 및 최적화

이 문서는 게임 내 몬스터 무리(Swarm)의 이동 로직과 이를 처리하기 위한 알고리즘의 원리 및 최적화 방식을 요약합니다.

## 1. 군집 알고리즘의 기본 원리

본 프로젝트의 군집 시스템은 개별 몬스터가 독립적으로 행동하면서도 하나의 무리처럼 움직이도록 설계되었습니다.

### 1.1 선두 기반 이동 제어 (Leader-based Movement)
- **원리**: 무리 내에서 가장 앞에 있는 몬스터(Front Minion)를 기준으로 전체 이동 가능 여부를 결정합니다.
- **로직**: `Swarm.cs`에서 매 프레임마다 가장 낮은 X 좌표를 가진 몬스터를 탐색하고, 해당 몬스터와 플레이어 사이의 거리가 특정 임계값(0.7f) 이상일 때만 무리 전체의 이동(`CanMinionsMove`)을 허용합니다.

### 1.2 협응적 상태 전이
- **원리**: 무리의 상태(이동 중, 정지, 넉백 등)가 무리 내의 모든 개체에게 즉각적으로 전파됩니다.
- **로직**: `Swarm.SetMoveStop(bool)` 호출 시 내부 리스트의 모든 몬스터 객체에 상태값을 전달하여 동기화된 동작을 보장합니다.

## 2. 최적화 방식 (Optimization Methods)

대량의 유닛을 효율적으로 처리하기 위해 다음과 같은 최적화 기법이 적용되었습니다.

### 2.1 중앙 집중식 거리 계산
- **최적화**: 모든 몬스터가 각자 플레이어와의 거리를 계산하는 대신, `Swarm` 클래스에서 무리의 선두 개체 하나만을 대상으로 거리 계산을 수행합니다.
- **효과**: 불필요한 연산 횟수를 $N$개에서 $1$개로 줄여 CPU 부하를 최소화합니다.

### 2.2 조건부 업데이트 (Culling Logic)
- **최적화**: `Swarm`은 활성화된 스테이지(`StageManager.CurrentSwarm`)일 때만 로직을 수행하며, 플레이어가 전환 중(`IsTransitioning`)이거나 강제 정지 상태일 때는 연산을 즉시 중단(Early Exit)합니다.

### 2.3 효율적인 개체 관리
- **구조**: 리스트(`List<Monster>`) 기반으로 개체를 관리하며, 개체 사망 시 이벤트(`OnDie`)를 통해 리스트에서 즉시 제거함으로써 유효하지 않은 객체에 대한 반복문을 방지합니다.

### 2.4 데이터 기반 난이도 조절
- **최적화**: 개별 몬스터 생성 시점에 층수(`floorCount`)에 따른 스탯 계산을 1회 수행하여, 런타임 중의 반복적인 스탯 계산 오버헤드를 제거했습니다.
